The repository contained a single commit with the message Initial commit. There was no analysis, no website, no data and no build system to review. The audit therefore became a statement of what was absent and what had to be created.

What was built

Repository structure created by this work

PathPurpose
data/The verified data snapshot. Six modules, one per domain: demographics, employment, tenant, hazards, analysis, flags. Every row carries value, unit, geography, as-of date, source organisation, source URL and a verification status. Rows that could not be confirmed carry a null value — they are never populated with an estimate.
model/projection.pyThe projection and decision model. Deterministic, no network calls, no randomness. Normalised to R. Six strategies, three coherent scenarios, fourteen declared assumptions each with a favourability direction, plus rank-stability and worst-case analysis.
build_site.pyThe static site generator. Reads the data modules and the model, writes plain HTML into docs/. Enforces the rule that an unverified row renders blank rather than a value.
site/The stylesheet and client-side behaviour. Plain CSS and plain JavaScript, no framework, no CDN, no external requests.
tools/check_links.pyExtracts every external URL from the generated site and validates it. Reports malformed URLs and any non-official domain appearing in a verified column.
tools/pii_scan.pyScans every generated file and data module for personal identifiers. Fails the build if any are found. This is the mechanical enforcement of the privacy directive.
docs/The published site — twenty-three pages served by GitHub Pages with no build step, so deployment cannot fail because of a toolchain.
COORDINATION.mdThe shared task board, session registry, file-ownership map and change log.
REPO_REVIEW.mdThe repository audit, recorded as a deliverable in its own right.
EXECUTIVE_SUMMARY.md · VERIFY.mdRepository-level summaries mirroring the site's Executive Summary and Methodology pages.
