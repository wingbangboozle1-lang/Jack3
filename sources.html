The verification standard

What each status means

Verified

The exact value was read on the official page linked in the row on 10 November 2026. The geography and period are stated beside it. Verification is of the observation, never of a forecast: a verified population decline is still not a prediction about this trade area.

Derived

Arithmetic performed on verified values. The method is written in the row, and scripts/validate.py recomputes each derived row from its components and fails the build if the published figure disagrees by more than a rounding step. No derived row rests on a private input.

Analysis

This project's judgement: route comparisons, risk balance, sequencing. Labelled everywhere, never counted as verified, never presented as an official statistic. The link on an analysis row points at the factual background it rests on, not at an endorsement.

Unverified / Needs review

No official source supplied the value, so the cell is blank and the row says what would close it. A blank is a finding, not an omission. Nothing on this site infers, interpolates or carries a value forward from another geography.

The privacy boundary

By design, not by policy alone

Placeholders only. The property is "Asset A" and the owner "Owner A". No street address, parcel or assessor number, owner name, contact detail, rent, net operating income, tax basis, debt term or lease document is collected, stored, published or committed to this repository. Anything of that kind is out of scope for this project and, if it ever arrives, belongs in a private file system that is never published.

No collection at runtime. These are static pages. There is no analytics, no tag manager, no form, no cookie, no third-party script or font, and no request to any server other than the one serving the page. GitHub Pages may retain standard access logs; that is the host's behaviour, not instrumentation added here.

Public links are the only outbound request. Clicking a citation opens the publisher's own website under that publisher's privacy terms.

Enforced in code. tools/pii_scan.py scans every published file and data module for email addresses, telephone numbers, street addresses, parcel and taxpayer identifier patterns, and identifying field values. It fails the build on any hit.

Reproducibility

Deterministic, offline, checked

Build

python3 scripts/build.py regenerates every page from data/evidence.json. No network access, no timestamps in output, byte-identical on rebuild.

Validate

python3 scripts/validate.py checks row provenance, blank-when-unverified, column integrity, internal links, derived arithmetic and prohibited embeds.

Stage

python3 scripts/stage_pages.py builds the exact Pages artifact and verifies that every internal link resolves inside it and every table row carries a registered official source.

The repository also contains research layers produced by earlier sessions (analysis/, advisory/, brief/, dashboard/, decision-file/, docs/, pages/). They are retained as an audit trail and excluded from the published artifact. Their figures and rankings are not re-verified here and are not endorsed; see the repository irregularities on Flagged for review.
